Informationen zum Umgang mit Daten innerhalb des WiFa Trainers.

2. Hosting über GitHub Pages

Das Frontend des WiFa Trainers wird über GitHub Pages bereitgestellt (Dienst von GitHub).

Beim Aufruf einer GitHub-Pages-Seite können insbesondere technische Verbindungsdaten wie die IP-Adresse verarbeitet und zu Sicherheitszwecken protokolliert werden. Diese Verarbeitung erfolgt technisch durch GitHub.

Rechtsgrundlage für die technisch erforderliche Bereitstellung und die IT-Sicherheit ist Art. 6 Abs. 1 lit. f DSGVO (berechtigtes Interesse an einer sicheren und zuverlässigen Bereitstellung der Website).

3. Registrierung und Anmeldung über Firebase Authentication

Für Registrierung, Anmeldung, E-Mail-Verifizierung, Passwortverwaltung und Authentifizierung wird Firebase Authentication (Google) verwendet.

Verarbeitet werden dabei insbesondere:

  • E-Mail-Adresse
  • Passwort (Verarbeitung über Firebase Authentication, nicht als Klartext im WiFa-Trainer-Code oder in Google Sheets gespeichert)
  • technische Authentifizierungsdaten
  • IP-Adresse
  • User-Agent
  • von Firebase erzeugte Benutzer-ID (UID)
  • gewählter Anzeigename (displayName)

Nach aktuellen Firebase-Angaben werden protokollierte IP-Adressen bei Firebase Authentication einige Wochen gespeichert. Andere Authentifizierungsinformationen bleiben grundsätzlich gespeichert, bis die Löschung des zugehörigen Firebase-Nutzers veranlasst wird. Nach Veranlassung der Löschung kann die Entfernung aus Live- und Backup-Systemen bis zu 180 Tage dauern.

Firebase Authentication wird laut Firebase ausschließlich über Rechenzentren in den USA betrieben. Für internationale Datenübermittlungen stellt Google Datenschutzmechanismen wie Angemessenheitslösungen bzw. Standardvertragsklauseln bereit.

4. Benutzerprofil und Cloud Firestore

Cloud Firestore wird für nutzerbezogene Daten und Lernstände genutzt. Für das Benutzerprofil wird ein Dokument unter users/{uid} angelegt.

Dabei werden im Profilbereich nach aktuellem Code-Stand folgende Felder gespeichert:

  • displayName
  • createdAt
  • updatedAt

Die UID dient zur eindeutigen Zuordnung der Daten zu einem angemeldeten Nutzerkonto. Der Zugriff wird über Firebase Authentication und Firestore Security Rules geregelt. Laut vorhandenen Regeln soll ein angemeldeter, E-Mail-bestätigter Nutzer jeweils nur auf die eigenen vorgesehenen Daten zugreifen können.

5. Speicherung von Lernständen und Lernergebnissen

Zur Darstellung des persönlichen Lernfortschritts werden Lernstands- und Ergebnisdaten in Cloud Firestore gespeichert und dem jeweiligen Nutzerkonto (UID) zugeordnet.

Je nach Funktion werden insbesondere folgende Daten verarbeitet:

  • Nutzerkennung (UID) und interne Attempt-ID
  • Datum/Zeitpunkt (timestamp)
  • Modul (z. B. wifa-trainer, pruefungssimulation, quiz)
  • Teilbereich, Fach, Thema
  • Frage-ID bzw. Quiz-Key / Question-Key
  • Frageinhalt (bei Prüfungssimulation je Aufgabe)
  • eigene Antwort
  • erreichte Punkte, maximal erreichbare Punkte, Prozentwert
  • Bewertung/Ergebnis (z. B. richtig, teilweise richtig, falsch, bestanden, nicht_bestanden)

Bei der Prüfungssimulation werden zusätzlich aufgabenbezogene Auswertungsdaten gespeichert (z. B. erkannte/fehlende Punkte, Musterlösung, Kennzeichnung, ob eine Skizze abgegeben wurde).

Zwecke der Verarbeitung sind persönlicher Lernstand, Fortschrittsdarstellung, Fehleranalyse, Wiederholung falsch beantworteter Fragen und Auswertung von Übungs- und Prüfungsleistungen.

6. Google Apps Script und Google Sheets

Für Backend-Funktionen nutzt der WiFa Trainer einen Google-Apps-Script-Webdienst. Darüber werden unter anderem Themen, Fragen, Quizdaten, Prüfungssimulationen, Karteikarten, Glossar- und Formelsammlungsinhalte bereitgestellt und KI-Funktionen ausgelöst.

Je nach Funktion können dabei insbesondere folgende Daten an Google Apps Script übertragen und dort verarbeitet werden:

  • Fach, Thema, Frage-ID, Quiz-Parameter
  • freie Antworten und Prüfungsantworten
  • Punkte- und Bewertungsdaten
  • Lernstandsrelevante Inhaltsdaten der jeweiligen Anfrage

Google Sheets ist in diesem Projekt als technischer Datenspeicher im Kontext der Google-Apps-Script-Funktionen eingebunden.

7. Einsatz der OpenAI API

Für bestimmte KI-gestützte Funktionen wird die OpenAI API verwendet, insbesondere für:

  • Auswertung freier Antworten
  • KI-gestützte Erklärungen im Bewertungskontext
  • Lernassistent „Frag Kilian“

Bei Nutzung dieser Funktionen werden die für die Anfrage erforderlichen Inhalte über die angebundene Backend-Schnittstelle verarbeitet. Dazu können insbesondere gehören:

  • gestellte Lernfrage
  • eingegebene Nutzerantwort
  • für die Bewertung notwendige Musterlösung, Stichpunkte und Bewertungskriterien
  • bei der Prüfungssimulation aufgabenbezogener Kontext (inklusive möglicher Skizzeninhalte)
  • bei „Frag Kilian“ die vom Nutzer eingegebene Frage

E-Mail-Adresse, Passwort oder vollständige Nutzerkontodaten werden im vorliegenden Frontend-Code nicht an OpenAI übermittelt.

Bitte geben Sie in Freitextfeldern keine sensiblen oder nicht erforderlichen personenbezogenen Daten ein.

Nach aktuellen offiziellen OpenAI-Angaben werden API-Eingaben und -Ausgaben standardmäßig nicht zum Training oder zur Verbesserung der Modelle verwendet, sofern nicht ausdrücklich eine Datenfreigabe aktiviert wurde. Protokolle zur Missbrauchsüberwachung können grundsätzlich bis zu 30 Tage gespeichert werden, sofern keine gesetzliche Pflicht oder produktspezifische Abweichung gilt.

Für Nutzer im Europäischen Wirtschaftsraum ist für entsprechende OpenAI-Vertragsbeziehungen grundsätzlich OpenAI Ireland Ltd. relevant. Internationale Übermittlungen können nach den OpenAI-Datenschutzbedingungen auf Angemessenheitsbeschlüssen oder Standardvertragsklauseln beruhen.

8. Speicherdauer und Löschung

Personenbezogene Daten werden grundsätzlich nur so lange gespeichert, wie sie für den jeweiligen Zweck benötigt werden oder gesetzliche Pflichten eine längere Speicherung verlangen.

  • Firebase Authentication: Authentifizierungsdaten grundsätzlich bis zur Löschung des Benutzerkontos; IP-Protokolle nach Firebase-Angaben einige Wochen; nach veranlasster Löschung kann die Entfernung aus Live- und Backup-Systemen bis zu 180 Tage dauern.
  • Lernstandsdaten in Firestore: Speicherung grundsätzlich, solange das jeweilige Nutzerkonto bzw. der gespeicherte Lernstand besteht; eine automatische Löschfrist ist im vorliegenden Code nicht hinterlegt.
  • OpenAI API: Daten können für Missbrauchsüberwachung grundsätzlich bis zu 30 Tage verarbeitet werden, soweit die eingesetzte API-Konfiguration keine abweichende Regel vorsieht.
  • GitHub Pages: Die Speicherdauer technischer Protokolldaten richtet sich nach den Vorgaben von GitHub.

9. Löschung des Benutzerkontos

Im aktuell vorliegenden Trainer-Code ist keine eigenständige Nutzeroberflächen-Funktion vorhanden, mit der Nutzer ihr Konto direkt selbst löschen können.

Sie können die Löschung Ihres Benutzerkontos und Ihrer personenbezogenen Daten über die unten genannte Kontaktmöglichkeit verlangen.

Wichtig: Im vorliegenden Code ist keine automatische Gesamtlöschung sämtlicher Firestore-Unterdaten (z. B. Lernstands-Historien) als Folge einer reinen Firebase-Account-Löschung implementiert. Löschungen müssen daher technisch je Datenbereich veranlasst werden.
